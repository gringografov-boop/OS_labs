## Использование API

Рабочие потоки запускаются вызовом `mt::CreateThread(&worker, &tasks[i], name)`. Главный поток также выполняет часть матрицы. По окончании вызываются `mt::ThreadJoin` и `mt::DestroyThreadHandle`. `mt::ThreadTerminate` в лабораторной не используется: штатное завершение не требует принудительного прерывания.

Существующий класс `mt::Thread` сохранён в общем компоненте и проверен после `Join`, но в основном алгоритме используется его низкоуровневый интерфейс. Это позволяет явно разделить ожидание и освобождение дескриптора и не вызывать принудительный `Stop` в нормальном сценарии.

Каждый участник пишет только в свой диапазон строк. После каждой итерации барьер гарантирует готовность всех строк перед сменой входного и выходного буферов. Эрозия и дилатация применяются независимо K раз к своим буферам. Окно на границе обрезается до границ матрицы.

Мьютекс запуска удерживает созданные потоки, пока не будет известно, что созданы все участники. При ошибке создания выставляется флаг отмены старта; уже созданные потоки завершаются до входа в барьер и ожидаются. Это предотвращает зависание на барьере с недостающими участниками. Отдельный мьютекс защищает диагностический вывод.

Добавленные ресурсы обёрнуты локальными RAII-классами. Это собственные обёртки над ОС, не `std::thread`, `std::mutex`, `std::barrier` и не `std::filesystem`.

## Параметры

| Ключ | Значение |
|---|---|
| `-i FILE` | Обязательная входная матрица |
| `-t P` | Максимум участников включая главный, по умолчанию 1 |
| `-k K` | Число итераций, по умолчанию 1; допустим 0 |
| `-w W` | Положительная нечётная сторона квадратного окна, по умолчанию 3 |
| `-o PREFIX` | Префикс результатов, по умолчанию `result` |
| `-v` | PID/TID и диапазоны строк |
| `-h` | Справка |

Участников не больше количества строк. При K=0 оба результата совпадают со входом, новые потоки не создаются. Первая пара целых чисел в матрице задаёт строки и столбцы, затем должно идти ровно rows*cols конечных вещественных значений. Пути могут содержать пробелы. Каталог выходного префикса должен существовать. Выходные файлы с совпадающими именами перезаписываются.

## Сборка из корня репозитория

```bash
cmake -S lab3 -B build-lab3-mt -DCMAKE_BUILD_TYPE=Release
cmake --build build-lab3-mt --target lab3 -j
./build-lab3-mt/bin/lab3/lab3 -i lab3/examples/matrix.txt -t 3 -k 1 -w 3 -o lab3/result -v
```

Для входной матрицы 3x3 из последовательных чисел 1..9 с окном 3 и K=1:

```text
Эрозия:
3 3
1 1 2
1 1 2
4 4 5

Наращивание:
3 3
5 6 6
8 9 9
8 9 9
```

Результаты записываются в `<PREFIX>_erosion.txt` и `<PREFIX>_dilation.txt`. `TIME_SECONDS` отражает измерение вычислительной части этого запуска, не готовое исследование ускорения.

## Демонстрация потоков

Во время достаточно долгого запуска в другом Linux-терминале:

```bash
ps -T -p PID
```

Вместо PID подставьте число из вывода программы. На маленьком примере программа может завершиться раньше запуска `ps`; для демонстрации нужна большая матрица и больше итераций. Результаты измерения ускорения и эффективности необходимо собирать на своей машине отдельно.
