# Лабораторная работа №4, вариант 5

Задача варианта та же, что в лабораторной работе №2: родитель читает числа,
дочерний процесс записывает составные числа в файл и завершает работу
вместе с родителем на простом или отрицательном числе. Вместо каналов данные
передаются через отображаемый файл (file mapping).

## Как устроено

- `code/include/ipc.h` — интерфейс канала и структура `Block`, лежащая в общей памяти.
- `code/ipc_posix.cpp` — Linux: `mkstemp` + `mmap(MAP_SHARED)`, уведомления через
  `sem_t` с `pshared = 1`, расположенные внутри того же отображаемого файла.
- `code/ipc_win.cpp` — Windows: временный файл, `CreateFileMapping` + `MapViewOfFile`,
  уведомления через именованные события (`CreateEvent` / `OpenEvent`).
- `code/parent/main.cpp`, `code/child/main.cpp` — диалог родителя и обработчик потомка.
  Разбор числа и проверка простоты берутся из `lab2_logic`.

Родитель создаёт файл, запускает потомка (`os::CreateProc`) и передаёт ему путь
к файлу и имя выходного файла. Потомок открывает выходной файл и сигналит
«готов». Затем для каждой строки: родитель кладёт её в `Block`, подаёт сигнал
запроса, потомок отвечает кодом (`Written`, `Ignored`, `Invalid`, `Stop`).
На конце ввода родитель отправляет команду `Stop`.

## Ошибки

- Ожидание сигналов идёт с периодом 100 мс; родитель проверяет `os::IsProcRunning`,
  потомок — жив ли родитель, поэтому смерть одного процесса не вешает другой.
- Ошибки записи в потомке передаются родителю текстом через `Block::errorText`.
- Строки длиннее 255 байт не помещаются в общий буфер и считаются некорректным вводом.
- Временный файл удаляется при завершении родителя.

    cmake --build build --config Release

    python3 lab4/tests/test_lab4.py build/bin/lab4/lab4_parent              # Linux
